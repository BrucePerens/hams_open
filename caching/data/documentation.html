1. Overview

The Caching module dramatically speeds up your website by saving essential design files (like JavaScript, CSS, and UI icons) directly in your browser's cache storage. This means that after the first time you visit, the website loads almost instantly because it doesn't have to wait for the same files to download over the internet again. This module acts like a high-speed personal library for your web browser, keeping the website's interface ready for use at a moment's notice.

2. How it Works

When you visit the site, a "Service Worker" is installed in your browser. This is a small, specialized script that acts as an intelligent assistant for your web requests.

  • Smart Asset Interception: It automatically identifies and saves Odoo's core assets and custom module files.
  • Local Fulfillment: On subsequent visits, these files are delivered from your computer's storage with near-zero latency, even on slow connections.
  • Automatic Background Updates: If the website design is updated (the server's scan of module files finds a newer file, or an administrator clicks Invalidate Cache Now), your browser will automatically detect the change on the next visit, download the new versions in the background, and seamlessly update your local cache. The page then shows an "Update Available" notice with a Reload button. Odoo's own compiled bundles update even without this, because each new version has a new address.

3. Important Safety Features

  • Intelligent Quota Management: Browsers limit how much data a Service Worker can save. To prevent the browser from "panicking" and deleting the entire cache, our assistant calculates exactly how much space is safe. It prioritizes small, essential UI files and automatically skips files above a size limit it calculates from the quota, while always setting aside 10MB of the quota for critical system bundles and overhead. When the browser's storage still goes over the quota, it removes the least recently used files first.
  • Privacy-First Architecture: The module only saves public technical assets required to display the website. It never saves your personal information, login credentials, or private data.
  • Real-time Compatibility: Live communication features like chat and notifications are explicitly bypassed by the caching system to ensure they always provide real-time updates.
  • High-Performance Delivery: The server does not rescan its files for every visitor: the scan result is kept in the shared Redis cache (for up to 24 hours) and in each server process's memory, and the Service Worker script template is kept in Redis for up to 24 hours, so checking for cache updates doesn't slow down the server, even with thousands of simultaneous visitors.

4. Administrator Controls

Administrators can fine-tune the caching behavior from the Website Settings (Configuration > Settings > Website section, in the Caching Service Worker block):

  • Safe Quota (MB): Adjust the maximum total size of files the browser is allowed to save. The default is 35MB, which is safe for most modern browsers. If your website's assets exceed this limit, the module will automatically prioritize essential files and skip the heaviest ones to maintain stability.
  • Force Cache Invalidation: If you have made major visual changes (like updating logos, brand colors, or custom scripts) and want to ensure all users see the update immediately on their next visit, click the Invalidate Cache Now button. This increments the cache version of the website you are configuring and forces all browsers to purge their saved assets for that website and download fresh ones.
  • PWA Theme Color & Background Color: Configure the colors injected into the dynamically generated /manifest.json. These settings dictate the browser's UI colors (such as the address bar and splash screen) when users install the site as a Progressive Web App (PWA).

5. Multi-Website Management

Each website in your Odoo system has its own independent cache settings. When you change the Safe Quota or click Invalidate Cache Now, it only affects the website you are currently configuring. This allows you to manage multiple brands and websites on the same server without them interfering with each other's performance optimization.

6. Troubleshooting

If the website layout appears inconsistent or "broken" after a major update, it is possible that some browsers are still holding onto stale cached files. An administrator can resolve this globally by using the Invalidate Cache Now button in the Website Settings. For individual users, a simple page refresh is usually enough to trigger the Service Worker's background update mechanism, but only once the server is offering a new Service Worker version (after Invalidate Cache Now or a new file scan). Until then, a refresh loads the same saved files again, because saved files are used without checking the server for a newer copy.

7. Developer Tips

For developers creating new modules:

  • Assets in /your_module/static/src/js/ and /your_module/static/src/css/ are automatically cached.
  • To force a cache refresh during development, you can either restart the Odoo server or use the Invalidate Cache Now button in settings. A restart is not always enough: when Redis is in use, the file-scan result cached there can last up to 24 hours. The button always works.
  • Avoid putting very large files in the static/ folder, as they might be excluded from the cache to preserve the storage quota. There is no fixed size cutoff: the limit is calculated from the quota and from the sizes of all modules' static files.
