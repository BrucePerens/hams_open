Backup Management User Guide

This module centralizes the management of your system's data protection. It supports both file-level backups (Kopia) and database-level backups (pgBackRest).

Core Features

  • Unified Dashboard: View the health and status of all your backup configurations in one place.
  • Automated Scheduling: Configure periodic snapshots and retention policies. Once a day the system queues a backup for every configuration, and once an hour it refreshes the list of snapshots and checks for stale backups.
  • Safe Execution: Operations run in the background to ensure the system remains responsive.
  • Integrity Checks: Automated restore drills verify that your data can actually be recovered. A drill runs only for a configuration that names a restore drill script, and at most once every 7 days.

Getting Started

1. Setup a Backup Configuration

Go to Backups > Management > Configurations. Create a new record, choosing the appropriate engine (Kopia for files, pgBackRest for databases) and filling in the Target / Stanza field: for Kopia, the path the worker passes to kopia snapshot create, which must lie inside one of the allowed backup directories when storage is a local directory; for pgBackRest, the stanza name (letters, digits and underscores only). You can also specify how many daily, weekly, and monthly snapshots to keep. For Kopia, click Apply Policies to push those numbers to the repository; for pgBackRest, only the daily number is used.

Saving a Kopia password or an S3/B2 secret key fails with an error if the server has no backup encryption key configured, because these secrets are stored encrypted.

2. Monitor via Dashboard

The Backup Dashboard (Backups > Management > Backup Dashboard) shows you at a glance if your backups are up to date. A configuration outlined in red and labeled STALE / FAILED has no recorded snapshot, or its newest recorded snapshot started more than 26 hours ago. The dashboard also displays the status of the most recent backup or sync job, providing real-time visibility into background operations.

3. Manual Execution

You can manually interact with backups in several ways:

  • Trigger Backup: Click "Run Backup Now" on the configuration form, or "Backup" on the Backup Dashboard, to immediately queue a new backup snapshot. The dashboard buttons are disabled while that configuration's latest job is still pending or processing.
  • Sync Snapshots: If snapshots were created outside of Odoo, click "Sync Snapshots" (or "Sync" on the dashboard) to update the local database with remote metadata.
  • Test Connection: Use the "Test Connection" action on a configuration to verify connectivity with Kopia or pgBackRest. It queues the same job as "Sync Snapshots"; check its result under Active Jobs.

4. Performing a Restore

In the event of data loss, navigate to Backups > Management > Snapshots. Select a known good snapshot and click the Restore Snapshot button, then Restore in the dialog. The dialog asks for a target directory, but for Kopia that value is not used: the files are always restored into /var/lib/odoo/backups/restore_<job id>, and the exact path is written into the restore job's log. Restoring a pgBackRest snapshot from this dialog is refused with an error; a pgBackRest restore must be run manually.

Security Note: Only users with "Backup Administrator" privileges can trigger restore operations, and the Backups menu is shown only to them. Creating configurations requires either that group or Odoo system administrator (Settings) rights, which also grant full access to configurations, snapshots and jobs.
