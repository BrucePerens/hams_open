Distributed Redis Cache

The Distributed Redis Cache module is a performance tool designed for Odoo environments with multiple servers. It ensures that when data changes on one server, every other server in your cluster discards its cached copy before it handles its next request, preventing "stale data" errors.

Overview

Normally, Odoo servers work independently. If you update a price or a user's permissions on Server A, Server B might not realize it for some time. This module links them all to a central "brain" (Redis) so they can share information about what has changed in real-time.

How it Works

  1. Detection: When a module changes data whose results it caches (or an administrator uses Invalidate Model Cache, described below), it sends an invalidation signal for that model through the database. This is not automatic for every record you save: each module decides which changes need a signal. When the change is saved, the cached entries for that model are deleted from Redis.
  2. Broadcast: A background service (the Cache Manager) immediately relays this change to the shared memory server (Redis) by increasing a shared counter.
  3. Refresh: Every Odoo server checks that counter at the start of each web request and before each scheduled job. When it sees the counter has changed, it clears its entire local memory cache (not just the data type that changed) and fetches fresh values as they are needed.
Smart Cleanup: In the shared Redis store, this module deletes only the entries for the data type (model) that changed, in the one database where it changed. Each server's small local memory cache is cleared as a whole, as described in step 3.

User Instructions

Managing the Cache

The Distributed Cache Manager is your central dashboard for ensuring synchronization across your Odoo cluster. Administrators can find these tools under the Distributed Cache menu in Odoo Settings.

Checking System Health

Click Check Redis Status to see if Odoo is talking to the shared memory server.

  • Green Success: Everything is working perfectly.
  • Red Error: The shared memory is unreachable. Don't worry—Odoo will automatically switch to "Fail-Open" mode and use standard local memory so your website stays online. ("Fail-open" means a cache failure lets requests through instead of blocking them: each server computes values itself and keeps them only in its own memory until Redis is reachable again.)

This button tests only the Odoo server you are connected to. It does not check the Cache Manager background service.

Configuration

Administrators can configure the Redis connection under the Settings menu in the Distributed Redis Cache section.

  • Redis Host: The hostname or IP address of your Redis server (default is redis).
  • Redis Port: The port Redis is listening on (default is 6379).
  • Redis Password: The password required to connect to your Redis instance.

When you save these settings, every Odoo server switches to the new connection (the other servers at their next request or scheduled job). They are not passed to the Cache Manager background service, which takes its Redis host, port and password from its own environment variables (REDIS_HOST, REDIS_PORT, REDIS_PASSWORD; default localhost, 6379, no password).

Manual Refresh

If you suspect a server is showing old information, you can manually trigger a refresh:

  1. Select the data type in the Model to Invalidate field (Odoo calls a data type a "Model", like User or Partner).
  2. Click Invalidate Model Cache.
  3. The shared Redis entries for that data type are deleted right away, and every other server clears its local memory at its next request or scheduled job (step 3 of How it Works).

Privacy and Isolation

This module is built for security. It automatically keeps data from different websites or different companies separate. A user on Website A will never see cached data intended for a user on Website B.

Technical Benefits

  • Secure: Uses "Zero-Sudo" architecture—background tasks have only the minimum access they need. ("Zero-Sudo" is this project's rule against Odoo's all-powerful sudo mode; the Cache Manager service runs as an ordinary system user and its database account can only connect and listen for signals.)
  • Reliable: Designed to never crash your site even if the cache server goes down.
  • Efficient: When deleting a data type's entries, it walks the Redis keys in batches of 1,000 (Redis SCAN) instead of listing every key in one blocking command (KEYS), so a large cache does not stall Redis.
Developer Tip: Use the @distributed_cache() decorator on your custom model methods to automatically benefit from cluster-wide caching and multi-tenant isolation.

Troubleshooting

If updates aren't appearing instantly:

  • Check Status: Use the "Check Redis Status" button.
  • Check the Service: Ensure the "Cache Manager" background service is active on your host. While it is stopped, other servers never receive the signal and keep their old local copies until the service is running again and a later change is signalled, or until they are restarted.
  • Be Patient: While usually instant, network signals can sometimes take a fraction of a second to travel between servers, and each server applies the signal only when it handles its next request or scheduled job.
