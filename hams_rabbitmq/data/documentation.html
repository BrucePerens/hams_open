RabbitMQ Global Connection Pool

The hams_rabbitmq module provides a secure global connection pool for RabbitMQ. This feature operates entirely in the backend and serves as an integration backbone for other services.

Note for Administrators: The RabbitMQ user, password, port and virtual host are read from the Odoo system parameters rabbitmq.user, rabbitmq.pass, rabbitmq.port and rabbitmq.vhost through zero_sudo's whitelisted parameter reader; an unset port falls back to 5672 and an unset virtual host to /. If the user and password parameters are not both set, they come from the RMQ_USER and RMQ_PASS environment variables, and with neither source nothing is sent (there is no guest fallback). The broker host comes from the RABBITMQ_HOST environment variable (default rabbitmq). There is no direct configuration menu for RabbitMQ.

The "pool" is one shared connection and channel that every module reuses. Messages are sent only after the database transaction that queued them commits; a message that cannot be sent (no connection, or the send fails) is logged and dropped. A dead pooled connection is retried once on a fresh connection.
