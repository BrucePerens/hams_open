# Rig support matrix

Generated by `tools/rig_support_matrix.py` from `data/hamlib-4.6.2/capability_matrix.json`, `rigs/*.toml` and `rigs/reports/verified.toml`. Do not edit by hand: `python3 tools/rig_support_matrix.py` rewrites it and `python3 tools/rig_support_matrix.py --check` (and the unit test) fail when it is stale.

Policy (2026-10-31): radioctl implements every model Hamlib lists, keeps this list of which ones a volunteer has actually verified, and makes its best effort to work out of the box. Every level below `hardware-verified` means no one has confirmed the description on a radio. The plan is [RIG_COVERAGE_PLAN.md](RIG_COVERAGE_PLAN.md); to help test, see [VOLUNTEER_TESTING.md](VOLUNTEER_TESTING.md).

Columns: **Tier** and **Family** are this tool's planning hints (not a statement of a radio's wire protocol); **Engine** is the radioctl protocol engine for the family, `-` when none exists; **Verification** is the highest `verified` state among the description's facts; **Verified by** comes from `rigs/reports/verified.toml`. Status: `described` = a `rigs/*.toml` exists; `engine only` = the engine exists, data missing; `needs variant` = an existing engine needs model variants; `needs engine` = a new engine; `odd device` = SDR board, network driver, parallel or dummy.
