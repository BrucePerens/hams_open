# The RX-888 Tools Boot the Receiver, Run radiod on Loopback and Measure What Comes In, Without Ever Transmitting

As the person (or the AI agent) running the bench, I want `bench_mcp` to bring up an RX-888 MkII direct-sampling HF receiver (0 to 30 MHz), start ka9q-radio's
`radiod` for it on the loopback interface, and then tell me what the receiver hears: the front-end state (sample rate, A/D overrange, RF gain), the level, noise
density and SNR at one frequency, a spectrum snapshot as a CSV, and a short I/Q or audio recording as a WAV file. This story documents every anchor of the
`rx888` driver: the module root (`daemons/bench_mcp/src/rx888/mod.rs`: settings, tool list, USB scan, firmware boot, the `radiod` process, front end, dispatch)
and the channel tools (`src/rx888/radio.rs`: tune, spectrum, capture and their helpers). The configuration example and the tool tiers are in the README
(section "RX-888 receiver").

Facts that apply to every entry. Nothing here can transmit: the RX-888 is a receiver, `radiod` is started with `iface = lo` and `ttl = 0` so its multicast never
leaves the host, and no tool needs a tier above `read_config` (`bench_rx888_status` and `bench_rx888_frontend` are `read_only`; the other six are
`read_config`). The transmit gate, the band check and the `full` tier therefore do not apply to any function below, and no entry keys a transmitter. The server
(`main.rs`) checks the instrument's tier, then holds the per-instrument lock (`bench_mcp_main_instrument_lock`) for the whole call, and runs the call on a blocking
thread, so two calls to one RX-888 never overlap and a call may block. A call that talks to `radiod` builds its own current-thread runtime and its own sockets, so
calls share no socket state. Every channel a tool opens has a 5 s lifetime that its reads renew, and is removed before the tool returns.

## The module root: settings, picking the instrument, the tool list

### `parse_config` [@ANCHOR: bench_mcp_rx888_config]

Reads the `rx888` keys of one instrument entry of the bench config into a `Config` and refuses anything unusable, so a bad path or group is reported when the config
loads and not when a tool runs. The result is held in `Instrument.rx888` and never changes afterwards. Called through the `module_config!` macro of `config.rs` when an entry's `driver` is `rx888`. `Config` also implements `Default` (the paths where ka9q-radio's `make install` puts them).

| Field (config key) | Type | Default | Meaning and check |
|---|---|---|---|
| `radiod` | `PathBuf` | `/usr/local/sbin/radiod` | The `radiod` binary. Absolute path required. |
| `driver_library` | `PathBuf` | `/usr/local/lib/ka9q-radio/rx888.so` | ka9q-radio's RX-888 driver, loaded by `radiod` (`library =`). Absolute. |
| `boot` | `PathBuf` | `/usr/local/sbin/rx888_boot` | The firmware loader program. Absolute. |
| `firmware` | `PathBuf` | `/usr/local/share/ka9q-radio/W1EUJ_0.1.0_FX3.img` | The FX3 firmware image. Absolute, because `rx888_boot` prefixes its own directory to a relative name. |
| `presets` | `PathBuf` | `/usr/local/share/ka9q-radio/presets.conf` | `radiod`'s presets file (its `[global] mode` names one). Absolute. |
| `status_group` | `Ipv4Addr` | `239.88.8.1` | `radiod`'s status (control) multicast group; must be an IPv4 multicast address. |
| `data_group` | `Ipv4Addr` | `239.88.8.2` | `radiod`'s data (RTP) multicast group; must be multicast. |
| `status_port` | `u16` | 5006 | Status port, 1 to 65535. |
| `data_port` | `u16` | 5004 | Data port, 1 to 65535. |
| `ssrc_base` | `u32` | 88000 | First of the three SSRCs the tools use (tune `+0`, spectrum `+1`, capture `+2`); 1 to 4294967280. |

Argument: `c`, `&Value`, borrowed, the instrument's JSON object. An absent key keeps its default; the keys are all optional. Returns `Ok(Config)`.

Errors (all `Err(String)`, naming the key): a path key that is not a string (`<key> must be a path`) or is relative (`<key> "..." must be an absolute path`); a group key
that is not a string or does not parse as an IPv4 multicast address (`<key> "..." is not an IPv4 multicast group`); a port that is not an integer from 1 to 65535
(`<key> must be 1 to 65535`); an `ssrc_base` outside 1 to 4294967280 (`ssrc_base must be 1 to 4294967280`); and the status and data endpoints being the same
group and port (`status and data must differ in group or port`). Pure: no file is opened, so a path that does not exist is accepted here and refused later by the
tool that needs it. No locking.

See also: test `config_has_install_defaults_and_refuses_relative_paths_and_unicast_groups`; `bench_mcp_rx888_radiod_config_text` and `bench_mcp_rx888_radiod_start` use
these fields.

### `instrument` [@ANCHOR: bench_mcp_rx888_instrument]

Picks the RX-888 a tool call is for, from all instruments of the bench. Private; called by `call_with` for every tool before anything else runs.

| Argument | Type | Meaning |
|---|---|---|
| `insts` | `&[Instrument]`, borrowed | Every configured instrument; only those of kind `Rx888` are considered. |
| `args` | `&Value`, borrowed | The tool's arguments; its optional string `instrument` names the one wanted. |

Returns a reference into `insts`. With a name: the RX-888 of that name. Without one: the only RX-888 when exactly one is configured. Errors: a name that is not a
configured RX-888 (`no rx888 instrument named "x"`, also when `x` names an instrument of another kind), none configured (`no rx888 instrument is configured`), or
several with no name given (`name the instrument: a, b`). Pure; no locking or I/O. See also: test `status_and_frontend_read_the_usb_tree_and_the_front_end`.

### `tool_defs` [@ANCHOR: bench_mcp_rx888_tool_defs]

Builds the MCP tool list the server advertises for the RX-888 driver, so a client sees only the tools its configuration allows. Called once when the server lists
its tools, with every instrument.

Argument: `insts`, `&[Instrument]`, borrowed. A tool of `SPECS` is listed when at least one RX-888 is configured at a tier at or above the tool's tier. So an RX-888 at
`read_only` lists `bench_rx888_status` and `bench_rx888_frontend`; at `read_config` or `full` it lists all eight (there is no tool above `read_config`). Returns a
`Vec<Tool>`, each with the tool name, the description prefixed with the tier in brackets (for example `[ReadConfig] RX-888: loads ...`) and a JSON schema object built
from the spec's `props` and `required` strings. A spec whose `props` text is not valid JSON, or whose schema is not an object, is silently left out. No errors, no I/O, no locking. See also: test
`status_and_frontend_read_the_usb_tree_and_the_front_end`.

### `number` [@ANCHOR: bench_mcp_rx888_number]

Reads one numeric argument with a range check; every tool uses it for its numbers so the ranges and the messages are the same. `pub(crate)`, used by `mod.rs` and
`radio.rs`.

| Argument | Type | Meaning |
|---|---|---|
| `args` | `&Value`, borrowed | The tool's arguments object. |
| `key` | `&str` | The argument name. |
| `default` | `Option<f64>` | Value used when the argument is absent or null; `None` makes the argument required. |
| `lo`, `hi` | `f64` | Inclusive bounds the value must lie in. |

Returns the number as `f64`. Errors: absent or null with no default (`<key> is required`); not a JSON number (`<key> must be a number`); not finite or outside
`lo..=hi` (`<key> <x> is outside <lo>..=<hi>`). A default is returned as given and is not range-checked. Integers are accepted as numbers; callers cast to an integer
type afterwards and do not check that a fractional value was meant to be whole (it is truncated). Pure. See also: test
`tune_reports_levels_snr_and_rate_and_removes_its_channel`.

## The USB scan and its JSON

### `UsbSeen` and `find_usb` [@ANCHOR: bench_mcp_rx888_find_usb]

Finds the RX-888s on the USB bus by reading the kernel's sysfs tree, so the tools know whether the device is present and whether its firmware is loaded without
opening the USB device. Callers: `status`, `boot` (before and while waiting) and `radiod_start`.

| Argument | Type | Meaning |
|---|---|---|
| `root` | `&Path`, borrowed | The directory to scan; production passes `/sys/bus/usb/devices` (the constant `USB_SYSFS`), tests a made-up tree. |

Returns `Vec<UsbSeen>` sorted by sysfs name: every entry of `root` whose `idVendor` is `04b4` (Cypress) and whose `idProduct` is `00f3` (the FX3 boot loader, an RX-888
without firmware) or `00f1` (the RX-888 running its firmware). An unreadable or missing `root`, or an entry without these files, yields nothing for that entry; there is
no error value. Read only; no locking.

Data structure `UsbSeen` (derives `Clone, Debug, PartialEq`, never serialised directly; `usb_json` makes the JSON):

| Field | Type | Meaning |
|---|---|---|
| `path` | `String` | The sysfs device name, such as `2-3.2`. |
| `product_id` | `String` | `00f3` unbooted or `00f1` booted, lower case as the kernel prints it. |
| `speed_mbps` | `Option<u32>` | Link speed in Mb/s from the kernel's `speed` file (`480` is USB 2, `5000` is USB 3); a fractional value (`1.5`) is truncated; `None` when the file is missing or not a number. |
| `product` | `Option<String>` | The product string when the device has one. |

The three constants `VID`, `PID_UNBOOTED` and `PID_BOOTED` hold the ids. See also: test `usb_scan_finds_the_loader_and_the_booted_device_only`.

### `usb_json` [@ANCHOR: bench_mcp_rx888_usb_json]

Turns a USB scan into the JSON the `usb` part of a status shows, and gives its state a sentence that names the next tool to call. Private; called by `status`, `boot` and
`radiod_start`.

Argument: `seen`, `&[UsbSeen]`, borrowed. Returns an object with `state` and `devices`. `state` is `"booted"` when any seen device is `00f1` (even if another is unbooted),
else `"unbooted (FX3 loader): call bench_rx888_boot"` when one is `00f3`, else `"not on the USB bus"`. `devices` has one object per device: `sysfs` (path), `usb_id`
(`04b4:00f1` form), `speed_mbps` (number or null), `product` (string or null) and `superspeed` (true when the speed is at least 5000, null when the speed is unknown).
Pure, no errors. See also: test `usb_scan_finds_the_loader_and_the_booted_device_only`.

## The `radiod` this server runs

### `running` [@ANCHOR: bench_mcp_rx888_running]

The process-wide table of the `radiod` programs this server has started: a lazily created `Mutex<HashMap<String, Running>>` keyed by instrument name. It exists so that
`status`, `boot`, `radiod_start` and `radiod_stop` agree on whether a `radiod` of ours is alive, and so the child handle (needed to reap it and read its exit status)
survives between tool calls.

Data structure `Running` (private): `child` (`std::process::Child`, owned), `config` (`PathBuf` of the written `radiod` config), `log` (`PathBuf` of the log file) and
`started` (`Instant`, used for the uptime in a status). It is created by `radiod_start`, read by `status`, and removed by `running_pid` (when the child has exited) or
`stop_pid`. It lives in memory only; a server restart forgets it, which is why the pid file `rx888-<name>.pid` also exists (see `stop_pid`).

Concurrency: a `std::sync::Mutex`, locked briefly for lookups and inserts; a poisoned lock is recovered and used (`into_inner`). Normally the per-instrument lock of the server
already serialises callers for one instrument, so this mutex only guards the map itself. No I/O. See also: test `status_and_frontend_read_the_usb_tree_and_the_front_end`.

### `running_pid` [@ANCHOR: bench_mcp_rx888_running_pid]

Says whether a `radiod` started by this server is still alive for an instrument, and cleans up one that has died.

Argument: `name`, `&str`, the instrument name. Returns `Some(pid)` when the table holds a child for that name and `try_wait` shows it has not exited; `None` when there is no
entry, or when the child has exited, in which case the entry is removed (the child is reaped by the `try_wait`). If `try_wait` itself fails, the child counts as alive. It
sends no signal and does no other I/O. Takes the table's mutex for the call (poison recovered). Called by `status`, `boot`, `radiod_start` (also in its wait loop, to see
the program exit at start) and indirectly by tests. See also: test `status_and_frontend_read_the_usb_tree_and_the_front_end`.

### `tail` [@ANCHOR: bench_mcp_rx888_tail]

Returns the last lines of a text file, for error messages and for the end of a stop result, so a person sees why `radiod` exited without opening the log.

| Argument | Type | Meaning |
|---|---|---|
| `path` | `&Path`, borrowed | The file, normally `rx888-<name>.log` in the output directory. |
| `n` | `usize` | How many lines at most. |

Returns a `Vec<String>` of at most `n` lines (all of them if the file is shorter). A file that cannot be read, or is not valid UTF-8, gives an empty list; there is no error. It
reads the whole file, which is small. See also: test `stop_uses_only_a_pid_file_that_names_this_radiod_with_this_config`.

### `loopback_multicast` [@ANCHOR: bench_mcp_rx888_loopback_multicast]

Tells whether multicast is enabled on the loopback interface, which `radiod` here needs because it runs on `lo` only. Called by `status` (reports it) and `radiod_start` (refuses
to start without it).

Argument: `sys_class_net`, `&Path`, borrowed; production passes `/sys/class/net`. It reads `<sys_class_net>/lo/flags`, a hexadecimal number the kernel prints with a `0x`
prefix, and returns true when the `IFF_MULTICAST` bit (0x1000) is set. A missing or unparsable file gives false. Read only. Turning it on needs a person with root:
`sudo ip link set dev lo multicast on` (it lasts until reboot); no tool does it. See also: test `status_and_frontend_read_the_usb_tree_and_the_front_end`.

### `radiod_config_text` [@ANCHOR: bench_mcp_rx888_radiod_config_text]

Builds the text of the configuration file `radiod` is started with: loopback only, TTL 0, no Avahi advertising, the RX-888 driver loaded by path. Called by `radiod_start`.

| Argument | Type | Meaning |
|---|---|---|
| `cfg` | `&Config` | Supplies the status and data groups, the presets path and the driver library path. |
| `description` | `&str` | Free text for the `description` key; double quotes and newlines are replaced by spaces so it cannot break the file. |
| `sample_rate_hz` | `u64` | `samprate`: 64800000 or 129600000 (the caller has already checked). |
| `rf_gain_db` | `Option<f64>` | Writes `gain = <g>` when given (the VGA gain, -8 to 34 dB, already range-checked); omitted keeps the driver default (RF AGC on). |
| `rf_atten_db` | `Option<f64>` | Writes `att = <a>` when given (0 to 31.5 dB in 0.5 steps); omitted leaves the driver default. |
| `fft_threads` | `u32` | `fft-threads`, 1 to 8. |

Returns the file text: a comment line, `[global]` with `hardware = rx888`, `status`, `data`, `iface = lo`, `ttl = 0`, `mode = usb`, `advertise = no`, `presets-file`,
`fft-threads` and `verbose = 1`, then `[rx888]` with `device = "rx888"`, `library`, `description` and `samprate`, then the optional `gain` and `att` lines. Pure: it writes no
file and cannot fail. Paths are written with `display()`, so a path that is not valid UTF-8 would be altered; the config check does not forbid it (unknown whether it can occur).
See also: test `radiod_start_checks_its_arguments_and_the_device_and_writes_a_loopback_config`.

### `radiod_start` [@ANCHOR: bench_mcp_rx888_radiod_start]

The tool `bench_rx888_radiod_start` (tier `read_config`): starts ka9q-radio's `radiod` for the booted RX-888 on loopback, niced to 10, and waits until its front end answers.
Called by `call_with`. It runs an external program as the server's user and writes three files; it does not transmit.

| Argument (JSON key) | Type | Range / default | Meaning |
|---|---|---|---|
| `inst` | `&Instrument` | | The instrument (carries the `Config`). |
| `args` | `&Value` | | Tool arguments below. |
| `usb_root` | `&Path` | | Sysfs USB root (tests pass a fake tree). |
| `sample_rate_hz` | integer | 64800000 (default) or 129600000 | Half rate covers 0 to 30 MHz; full rate needs a faster host. |
| `rf_gain_db` | number | -8 to 34; omitted = driver default | VGA gain in high-gain mode. |
| `rf_atten_db` | number | 0 to 31.5 in 0.5 dB steps; omitted = 0 | Attenuator. |
| `fft_threads` | integer | 1 to 8, default 2 | radiod's FFT threads. |

Order of checks, each an `Err(String)`: this server already runs one for the instrument (`radiod already runs for <name> (pid N)`); a pid file `rx888-<name>.pid` in the output
directory names a live process that `is_our_radiod` confirms (`a radiod started earlier ... still runs (pid N, started by a previous server); stop it with bench_rx888_radiod_stop`);
a bad sample rate, gain, attenuation (not a 0.5 dB step) or thread count; the device not booted (`the RX-888 is not booted (<state>). Next: bench_rx888_boot.`); loopback multicast off
(the message gives the one command a person must run); `radiod`, `driver_library` or `presets` not a file; the files `rx888-<name>.conf` and `.log` cannot be written.

Side effects, in `BENCH_MCP_OUT` (`out_dir`): writes `rx888-<name>.conf` (from `radiod_config_text`), creates `rx888-<name>.log` (the program's stdout and stderr), starts
`nice -n 10 <radiod> -v <conf>` with stdin closed, writes the pid into `rx888-<name>.pid`, and stores the child in `running`. It then loops for up to 15 s (`START_WAIT`): if
the program exits, returns `radiod exited at start. Log: [last 15 lines]`; if a front-end poll (500 ms) succeeds, returns `{started: true, pid, config, log, front_end}`; on timeout it
stops the program with `stop_pid` and returns `radiod did not answer within 15s; stopped it. Log: [...]`. The call blocks for the whole time under the instrument lock.

Transmit safety: none applies; the receiver has no transmit path, the multicast is loopback with TTL 0, and the tier needed is `read_config`. See also: test
`radiod_start_checks_its_arguments_and_the_device_and_writes_a_loopback_config`; the hardware check `tests/hil_rx888.rs` (`--ignored`).

### `is_our_radiod` [@ANCHOR: bench_mcp_rx888_is_our_radiod]

Checks that a process id really is the `radiod` this server started for an instrument, so a stale pid file (after a reboot or a restart, when the number may belong to anything
else) is never trusted. Private; called by `radiod_start` and `stop_pid`.

| Argument | Type | Meaning |
|---|---|---|
| `pid` | `u32` | The pid read from `rx888-<name>.pid`. |
| `radiod` | `&Path` | The configured `radiod` binary. |
| `config` | `&Path` | The config file path this server writes for the instrument. |

Reads `/proc/<pid>/cmdline` (NUL-separated arguments) and returns true only when its first argument equals the `radiod` path as text and the config path is one of the
arguments. False when the file cannot be read (no such process). Note that a `radiod` started through `nice -n 10 <radiod> ...` has `nice` as its first argument until `nice` execs
`radiod`; after that exec the command line is `radiod` first, which is the state this checks (the exec happens immediately). Read only; no signals. See also: test
`stop_uses_only_a_pid_file_that_names_this_radiod_with_this_config`.

### `stop_pid` [@ANCHOR: bench_mcp_rx888_stop_pid]

Stops the `radiod` of an instrument: the child this process holds, or else the process named by its pid file when `/proc` proves it is that `radiod` with this server's config (so a
restarted server can still stop what an earlier one started). Never by name or pattern; only one verified pid is ever signalled. Called by `radiod_stop` and by `radiod_start` when
the program does not answer in time.

Argument: `inst`, `&Instrument`. Steps: remove the entry from `running`; if there is none, read `rx888-<name>.pid` and require `is_our_radiod`; send `SIGTERM` (`libc::kill` on
that pid); poll every 100 ms for up to 5 s for it to go (the child's `try_wait`, or `/proc/<pid>` disappearing); if still alive, send `SIGKILL` and wait for it; remove the pid file.

Returns `{stopped: true, pid, exit, sigkill_needed, log_tail}` where `exit` is the child's exit status text, `"exited"` (found gone, adopted pid) or `"killed"` (adopted pid after
`SIGKILL`) and `log_tail` is the last 5 log lines. Errors: no entry and no readable pid file (`no radiod was started by this server`); the pid file names something that is not this
`radiod` with this config (`pid N in <file> is not radiod with <conf>; nothing was stopped and the stale pid file was removed`, and the file is deleted); a pid that does not fit
`pid_t`. Side effects: signals one process, deletes the pid file, blocks up to about 5 s under the instrument lock. `sigkill_needed` is true when `SIGTERM` was not enough. The `unsafe`
`kill` is sound because the pid is our own child or was verified through `/proc` immediately before; there is a small window between that check and the signal (unknown whether it matters here).
See also: test `stop_uses_only_a_pid_file_that_names_this_radiod_with_this_config`.

### `radiod_stop` [@ANCHOR: bench_mcp_rx888_radiod_stop]

The tool `bench_rx888_radiod_stop` (tier `read_config`): stops the `radiod` this server started for the instrument. It is `stop_pid` with no other logic; called by `call_with`. Argument:
`inst`, `&Instrument`. Returns what `stop_pid` returns (`stopped`, `pid`, `exit`, `sigkill_needed`, `log_tail`) or its errors, in particular `no radiod was started by this server` when there is nothing to
stop; a `radiod` someone else started is never touched. It blocks up to about 5 s under the instrument lock. Does not transmit. See also: test
`stop_uses_only_a_pid_file_that_names_this_radiod_with_this_config`.

## Talking to `radiod`: runtime, control socket, front end

### `runtime` [@ANCHOR: bench_mcp_rx888_runtime]

Builds the small asynchronous runtime a tool call needs to use the async `radiod_client` sockets from its blocking thread. `pub(crate)`; called at the start of `status`, `frontend`,
`radiod_start`, `tune`, `spectrum` and `capture`, once per call. No arguments. Returns a current-thread `tokio::runtime::Runtime` with I/O and timers enabled. The call runs on a blocking
thread outside any runtime (the server uses `spawn_blocking`), so `block_on` on this runtime is allowed. Error: `cannot start a runtime: <io error>` (for example out of file descriptors).
The runtime is dropped when the call ends, closing the sockets opened on it. See also: test `status_and_frontend_read_the_usb_tree_and_the_front_end`.

### `control` [@ANCHOR: bench_mcp_rx888_control]

Opens the control socket to `radiod`'s status group on loopback, over which the tools send commands and read status. `pub(crate)`; called by `front_end`, `tune`, `spectrum` and `capture`.

| Argument | Type | Meaning |
|---|---|---|
| `cfg` | `&Config` | Gives `status_group` and `status_port`. |
| `rt` | `&Runtime` | The call's runtime, borrowed; the socket lives on it. |

Returns a `radiod_client::net::Control` joined to the group on interface `127.0.0.1`, with `radiod_client`'s default command policy (frequencies 10 kHz to 30 MHz, at most 8192 bins,
bin width at least 1 Hz, averaging at most 64, a lifetime at most 15000 frames of 20 ms; the library refuses a command outside it before sending). The socket sends with TTL 0, so nothing leaves
the host. Error: `cannot join radiod's status group <group>:<port> on loopback (<error>). Next: is loopback multicast on (bench_rx888_status)?`. Side effect: opens a UDP socket and joins a
multicast group; closed when the `Control` is dropped. See also: test `status_and_frontend_read_the_usb_tree_and_the_front_end`.

### `front_end` [@ANCHOR: bench_mcp_rx888_front_end]

Reads the front end's own status from `radiod`, so a tool can tell whether `radiod` is up and answering and what the receiver is doing. `pub(crate)`; called by `status` (800 ms), `frontend` (2 s),
`radiod_start` (500 ms per try) and `spectrum` (2 s, to learn the sample rate).

| Argument | Type | Meaning |
|---|---|---|
| `cfg` | `&Config` | Selects the status group and port. |
| `rt` | `&Runtime` | The call's runtime. |
| `wait` | `Duration` | How long to wait for the answer. |

Returns the `ChannelStatus` of the front end (the poll uses SSRC 0, creates no channel and carries no tag). Errors: the control socket cannot open (see `control`); the read fails
(`radiod front-end read failed: <e>`); or no answer within `wait` (`radiod does not answer on <group>:<port> within <wait>. Next: bench_rx888_status, then bench_rx888_radiod_start.`). Opens
its own control socket each call and blocks for up to `wait`. See also: test `status_and_frontend_read_the_usb_tree_and_the_front_end`.

### `front_end_json` [@ANCHOR: bench_mcp_rx888_front_end_json]

Turns a front-end status into the JSON the status and front-end tools return. `pub(crate)`. Argument: `fe`, `&ChannelStatus`, borrowed. Returns an object whose keys are:

| Key | Meaning |
|---|---|
| `description` | The text from the `description` line of the `radiod` config. |
| `input_sample_rate_hz` | The ADC sample rate, S/s. |
| `real_samples` | True for a real (direct-sampling) front end such as this one. |
| `ad_bits` | ADC width in bits. |
| `ad_overrange_count` | A/D overrange events counted so far. |
| `samples_since_overrange` | Samples since the last overrange. |
| `rf_gain_db`, `rf_atten_db` | RF gain and attenuation in dB; null when absent or not finite. |
| `rf_agc` | Whether the RF AGC is on. |
| `if_power_dbfs` | IF power in dB re full scale; null when absent or `-inf`. |
| `front_end_running` | True only when the IF power is a finite number. |
| `rf_level_cal_db` | Level calibration, dB; null when not finite. |
| `usable_low_hz`, `usable_high_hz` | The usable edges of the front end; null when not finite. |

Absent fields come out as null. While no channel exists the front end idles and reports an IF power of `-inf`, so that value is null and `front_end_running` is false (which is not a fault). Pure,
no errors. See also: test `status_and_frontend_read_the_usb_tree_and_the_front_end`.

## The tools of the module root

### `status` [@ANCHOR: bench_mcp_rx888_status]

The tool `bench_rx888_status` (tier `read_only`): one look at everything that decides whether the RX-888 can be used, changing nothing. Called by `call_with`.

| Argument | Type | Meaning |
|---|---|---|
| `inst` | `&Instrument` | The instrument. |
| `usb_root` | `&Path` | Sysfs USB root. |
| `instrument` (JSON) | string, optional | Which RX-888, when several are configured (resolved by `instrument`). |

Returns an object: `usb` (from `usb_json`), `radiod` (`{running: true, pid, config, log, uptime_s}` for the child this server holds, otherwise `{running: false, note}` with a note that another `radiod`
may still answer), `front_end` (`front_end_json`, or `{answering: false, why}` when nothing answers within 800 ms), `loopback_multicast` (bool) and `groups` (`status` and `data` as
`group:port`). A missing front end is not an error. The only error is the runtime failing to start. It reads sysfs and briefly opens a multicast socket; it starts, stops and writes nothing,
and does not transmit. Blocks about 0.8 s when `radiod` is absent. See also: test `status_and_frontend_read_the_usb_tree_and_the_front_end`; `bench_mcp_rx888_usb_json`, `bench_mcp_rx888_front_end_json`.

### `frontend` [@ANCHOR: bench_mcp_rx888_frontend]

The tool `bench_rx888_frontend` (tier `read_only`): the front end's own status (sample rate, A/D overrange count, RF gain, attenuation, AGC, IF power) read from a running `radiod`. Argument: `inst`,
`&Instrument` (the optional `instrument` key picks it). Returns `front_end_json` of a front-end poll that waits up to 2 s. Errors: the runtime or control socket fails, or `radiod` does not answer (the
messages of `front_end`, which name `bench_rx888_status` and `bench_rx888_radiod_start` as next steps). Unlike `status` it needs `radiod` running and fails otherwise. Changes nothing; no transmit.
See also: test `status_and_frontend_read_the_usb_tree_and_the_front_end`.

### `boot` [@ANCHOR: bench_mcp_rx888_boot]

The tool `bench_rx888_boot` (tier `read_config`): loads the FX3 firmware into the RX-888's RAM with ka9q-radio's `rx888_boot`, so the device can run. Called by `call_with`. Arguments: `inst`
(`&Instrument`, supplies `boot` and `firmware`) and `usb_root` (`&Path`); the tool has no arguments of its own besides `instrument`.

Checks, in order, each returning early: this server runs a `radiod` for the instrument (`Err`: stop it first with `bench_rx888_radiod_stop`); a booted device is already present (returns
`{already_booted: true, usb}` and runs nothing); no unbooted device is present (`Err`: check the cable, or power-cycle its hub port with `bench_usb_port_power`); the firmware path is not a file
(`Err`, saying to set `firmware`). It then runs `<boot> <firmware>` and waits for it to finish (no time limit of its own; unknown how long the loader can hang), keeping its stdout and stderr, then polls the
sysfs tree every 250 ms for up to 20 s (`BOOT_WAIT`) for `04b4:00f1`. Success returns `{booted: true, sysfs, speed_mbps, superspeed, note, loader_output}`, where `note` says whether the link is USB 3
(the full rate is possible) or not (run at a rate USB 2 can carry, or move the cable). Failure to come back returns an `Err` quoting the loader's output and saying to power-cycle the hub port once more
(not to unbind the USB controller). Failure to start the program: `cannot run <boot>: <e>`.

Side effects: runs a program as the server's user; the device leaves the USB bus and re-enumerates; the firmware is loaded to RAM only, nothing is written to flash. It blocks under the instrument lock up
to the loader's run time plus 20 s. No transmit. See also: test `boot_runs_nothing_when_the_device_is_absent_or_already_booted`; `bench_mcp_rx888_find_usb`, `bench_mcp_rx888_usb_json`.

### `call` [@ANCHOR: bench_mcp_rx888_call]

The entry the server calls for an RX-888 tool: it runs the tool against the real USB sysfs tree. `call(insts, name, args)` is `call_with(Path::new("/sys/bus/usb/devices"), insts, name, args)`. Registered
in the driver table of `main.rs` next to `tool_defs`. Arguments and results are those of `call_with`. See also: test `status_and_frontend_read_the_usb_tree_and_the_front_end`.

### `call_with` [@ANCHOR: bench_mcp_rx888_call_with]

The dispatcher: finds the tool, picks the instrument, enforces the tier and runs the tool. Taking the USB root as an argument lets tests point it at a made-up tree.

| Argument | Type | Meaning |
|---|---|---|
| `usb_root` | `&Path` | Sysfs USB root passed to the tools that scan it (`status`, `boot`, `radiod_start`). |
| `insts` | `&[Instrument]` | All configured instruments. |
| `name` | `&str` | The tool name, one of the eight in `SPECS`. |
| `args` | `&Value` | The tool arguments. |

Returns the tool's JSON `Value`. Errors: an unknown tool (`unknown tool <name>`); the instrument errors of `instrument`; a tool above the instrument's tier (`<name> needs tier ReadConfig; "<inst>" is
configured at ReadOnly`), refused before anything runs; and every error of the tool itself. A tool name in `SPECS` that has no match arm gives `<name> does not apply to "<inst>"` (cannot happen while
the table and the match agree). The tier check duplicates the server's own check in `main.rs` and keeps the module safe when called directly. It takes no lock itself (the server holds the instrument lock
around the call). Transmit gate: not applicable, all eight tools are receive only. See also: test `status_and_frontend_read_the_usb_tree_and_the_front_end`.

## Channel tools: `radio.rs`

### `ssrc` [@ANCHOR: bench_mcp_rx888_ssrc]

Makes the SSRC (the 32-bit stream id of a `radiod` channel) of one of the instrument's three fixed channel slots. Private. Arguments: `cfg` (`&Config`, whose `ssrc_base` is the base) and `which` (`u32`: 0 for
tune, 1 for spectrum, 2 for capture). Returns `Ssrc` of `ssrc_base + which`. Error `ssrc: <reason>` when `radiod_client` refuses the value (0 and `u32::MAX` are reserved; the `ssrc_base` range check keeps
real configurations clear of both). `ssrc_base + which` cannot overflow because `ssrc_base` is at most 4294967280. Using fixed numbers means a channel a dead server left behind is found and replaced, and
expires by its own lifetime. Pure. See also: test `modes_edges_ssrcs_and_paths`.

### `mode_arg` [@ANCHOR: bench_mcp_rx888_mode_arg]

Reads the optional `mode` argument of `tune` and `capture`. `pub(crate)`. Arguments: `args` (`&Value`) and `default` (`Mode`, used when `mode` is absent). Returns `Mode::Usb`, `Lsb`, `Cw`, `Am` or `Fm` for
the strings `usb`, `lsb`, `cw`, `am`, `fm` (lower case only), or `default`. Error: any other string (`mode "x" is not usb, lsb, cw, am or fm`). A `mode` that is present but not a string (a number, say) is an error (`mode must be text`); null counts as absent. Tune and an audio capture default to `Am`. Pure. See also: test `modes_edges_ssrcs_and_paths`.

### `edges` [@ANCHOR: bench_mcp_rx888_edges]

Computes where a passband of a given width sits for a mode, so a `bandwidth_hz` request can be sent to `radiod` as low and high edges. `pub(crate)`. Arguments: `mode` (`Mode`) and `width` (`f64`, Hz; the
tool has already limited it to 100 to 24000). Returns `(low, high)` in Hz relative to the carrier, as `f32`:

| Mode | Low edge | High edge |
|---|---|---|
| `Usb` | 50 | 50 + width |
| `Lsb` | -50 - width | -50 |
| `Cw` | 600 - width/2 | 600 + width/2 (centred on the 600 Hz beat note) |
| `Am`, `Fm`, `Iq`, `Sam` | -width/2 | width/2 |
| `SamLower` | 100 - max(width, 200) | 100 |
| `SamUpper` | -100 | max(width, 200) - 100 |

The numbers follow the `radioctl` radiod channel (stated in the code comment). Pure, no errors. Only the first five modes can come from `mode_arg`; the rest are for completeness. See also: test
`modes_edges_ssrcs_and_paths`.

### `ask` [@ANCHOR: bench_mcp_rx888_ask]

Sends one command to `radiod` and returns the status it answers with, giving the channel tools one error format for a failed or unanswered command. Private.

| Argument | Type | Meaning |
|---|---|---|
| `rt` | `&Runtime` | The call's runtime. |
| `c` | `&mut Control` | The open control socket. |
| `cmd` | `&Command` | The command (open a channel, filter, poll, gain, spectrum). |
| `wait` | `Duration` | How long to wait for the acknowledging status: `ACK` (1 s) for a running channel, `OPEN_ACK` (10 s) for the command that opens a channel (the first channel starts the front end and plans its FFT), `SPECTRUM_FIRST_WAIT` (10 s). |

Returns the `ChannelStatus` that carries the command's tag. Errors: the command is refused or the send fails (`radiod command failed: <e>`, which includes `radiod_client`'s policy refusals); no answer in
`wait` (`radiod did not acknowledge within <wait>. Next: bench_rx888_status.`). Sends a multicast datagram on loopback and blocks up to `wait`. See also: test
`tune_reports_levels_snr_and_rate_and_removes_its_channel`.

### `remove` [@ANCHOR: bench_mcp_rx888_remove]

Deletes a channel the tool opened. Private; called by `tune`, `spectrum` and `capture` after their work, on success and on error. Arguments: `rt` (`&Runtime`), `c` (`&mut Control`) and `s` (`Ssrc`). Sends
`Command::Remove` and waits up to `ACK` (1 s) for the acknowledgement. Returns nothing and ignores every error: it is best effort, because a channel that is not removed expires by its own 5 s lifetime in
any case. Side effect: one multicast datagram on loopback. See also: test `tune_reports_levels_snr_and_rate_and_removes_its_channel` (which asserts the channel is "removed at the end").

### `snr_db` [@ANCHOR: bench_mcp_rx888_snr_db]

Computes a signal-to-noise estimate from a measured power, for the `snr_db` field of a tune result. `pub(crate)`. Arguments: `baseband_db` (`f64`, the channel's baseband power in dB, which is signal plus
noise in the passband) and `noise_in_band_db` (`f64`, the noise in the same band, dB). The result is `10 log10(P/N - 1)` with `P/N = 10^((baseband - noise)/10)`, in dB; when `P/N - 1` is at or below
0.001 (the power is at or below the noise, or less than 0.0004 dB above it) the result is the floor value -30.0. Never NaN for finite inputs. Pure. See also: test
`snr_is_signal_over_noise_with_a_floor`.

### `tune` [@ANCHOR: bench_mcp_rx888_tune]

The tool `bench_rx888_tune` (tier `read_config`): opens a receive channel at a frequency, lets it settle and averages several status reads to report level, noise, SNR and the input sample rate. Needs `radiod`
running. Receive only.

| Argument (JSON key) | Type | Range / default | Meaning |
|---|---|---|---|
| `freq_hz` | number | 10000 to 30000000, required | Carrier (dial) frequency in Hz. |
| `mode` | string | `usb`, `lsb`, `cw`, `am` (default), `fm` | Demodulator. |
| `bandwidth_hz` | number | 100 to 24000; omitted = the mode's own | Passband width, set with a filter command using `edges`. |
| `readings` | integer | 1 to 50, default 10 | How many status reads to average, 100 ms apart. |

Sequence: opens the channel at SSRC `ssrc_base + 0` with a 5 s lifetime (up to 10 s to be acknowledged), optionally sets the filter, waits 500 ms, polls `readings` times, and always removes the channel
(`remove`) before looking at the result. The mean baseband power and noise density come from the finite readings only. The noise in the passband is `noise density + 10 log10(bandwidth)`, and the SNR is
`snr_db` of that.

Returns an object: `frequency_hz`, `mode`, `passband_hz` (`[low, high]`), `baseband_power_db`, `noise_density_db_per_hz`, `noise_in_passband_db` and `snr_db` (null when the passband width is not positive), `agc`,
`channel_gain_db`, `output_level_dbfs`, `readings`, `input_sample_rate_measured_sps` (from the input sample counter over the whole interval; null when the counter did not advance), `rate_interval_s`,
`rate_resolution_fraction` (the 20 ms block over the interval, so more readings give a finer rate) and a `note` (levels are dB re full scale referred to the input, not dBm; -30 dB SNR means no signal above the noise).

Errors: any out-of-range or missing argument (messages of `number` and `mode_arg`); the runtime or control socket; a command that is not acknowledged; `radiod sent no baseband power` or `no noise density`. The
channel is removed in every case. It blocks about 0.6 s plus 0.1 s per reading under the instrument lock. Opens a UDP socket; writes no file; does not transmit. See also: test
`tune_reports_levels_snr_and_rate_and_removes_its_channel`.

### `out_path` [@ANCHOR: bench_mcp_rx888_out_path]

Makes a new file name for a CSV or WAV the tools write, in the server's output directory, so two results never overwrite each other. Private. Arguments: `stem` (`&str`, such as `rx888_<name>_spectrum`) and `ext`
(`&str`, `csv` or `wav`, without the dot). Returns `<out_dir>/<stem>_<milliseconds since the Unix epoch>.<ext>`, where `out_dir` is `BENCH_MCP_OUT` or, when unset, `bench_mcp` under the system temp directory (created if
missing). If the clock is before the epoch the milliseconds are 0. It does not create the file or check that the name is free: two calls in the same millisecond with the same stem would give the same name; the instrument name is in the stem and the per-instrument lock serialises one instrument's calls, so this does not happen in normal use. See also: test `modes_edges_ssrcs_and_paths`; `bench_mcp_main_out_dir`.

### `peaks` [@ANCHOR: bench_mcp_rx888_peaks]

Finds the strongest signals in a spectrum, for the `peaks` list of a spectrum result. `pub(crate)`.

| Argument | Type | Meaning |
|---|---|---|
| `bins` | `&[(f64, f32)]` | The spectrum as (frequency in Hz, level in dB), in frequency order. |
| `floor` | `f64` | The noise floor, dB (the median level). |
| `above_db` | `f64` | A peak must be at least this far above `floor` (10 dB in the one caller). |
| `count` | `usize` | The most peaks to return; 0 gives none. |

Returns up to `count` pairs (frequency, level) strongest first. A bin counts when its level is finite, at least `floor + above_db`, and not below either neighbour (a neighbour that is NaN or infinite cannot hide a
peak, and the ends have one neighbour). Candidates are taken strongest first and a candidate within 2 bins of an already chosen, stronger one is dropped, so one tone does not fill the list. No errors, pure. See also:
test `peaks_are_local_maxima_above_the_floor_strongest_first_and_apart`.

### `spectrum` [@ANCHOR: bench_mcp_rx888_spectrum]

The tool `bench_rx888_spectrum` (tier `read_config`): one spectrum snapshot from `radiod`, saved as a CSV and summarised. Needs `radiod` running. Receive only.

| Argument (JSON key) | Type | Range / default | Meaning |
|---|---|---|---|
| `center_hz` | number | 0 to 64800000, default 16200000 | Centre frequency, Hz. |
| `span_hz` | number | 1000 to 129600000, default 32400000 | Width covered, Hz; at most half the front end's sample rate. |
| `bins` | integer | 64 to 16000, default 1024 | Number of bins; each is `span/bins` wide. |
| `averaging` | integer | 1 to 64, default 10 | FFTs averaged. |
| `peaks` | integer | 0 to 50, default 10 | Peaks to list. |

Reads the front end first (2 s) for its sample rate, and refuses a span wider than `max_spectrum_span_hz` (half the rate for this real front end: 32.4 MHz at 64.8 Msps, since wider requests come back with half the
bins zero). It opens a spectrum channel at SSRC `ssrc_base + 1`, sends the command twice, 300 ms apart (the second response has the requested averaging behind it), each waiting up to 10 s because the FFT may be being
planned, and removes the channel. It writes `rx888_<name>_spectrum_<ms>.csv` in `BENCH_MCP_OUT` with a comment line, a `freq_hz,level_db` header and one row per bin (`%.1f` Hz, `%.2f` dB; levels are dB re full
scale per bin, input-referred, not dBm).

Returns `csv` (path), `center_hz`, `span_hz`, `bins`, `bin_hz`, `noise_bandwidth_hz`, `fft_n`, `averaging`, `floor_db` (median of the finite levels), `min_db`, `max_db`, `zero_bins` (bins exactly 0, a sign of a span the
front end cannot fill), `peaks` (list of `{freq_hz, level_db, above_floor_db}` for peaks 10 dB over the floor, from `peaks`) and `front_end` (`ad_overrange_count`, `rf_gain_db`). Errors: argument ranges; the front end
does not report a sample rate; the span is too wide (message gives the maximum); the command is refused or not acknowledged; `radiod returned no spectrum bins`; the CSV cannot be written. Blocks several seconds at most
under the instrument lock; no transmit.

Note (unverified in this story): the control socket's default policy limits `center_hz` to 30 MHz and the bin count to 8192, while this tool accepts up to 64.8 MHz and 16000; a request above the library limit would come
back as `radiod command failed: ...` from `ask`. See also: test `spectrum_writes_a_csv_finds_the_tone_and_refuses_a_span_wider_than_half_the_rate`.

### `wav_header` [@ANCHOR: bench_mcp_rx888_wav_header]

Builds the 44-byte header of a 16-bit PCM WAV file, so a capture can be written with the standard library only. `pub(crate)`. Arguments: `rate` (`u32`, samples per second), `channels` (`u16`, 1 or 2 here) and `frames`
(`u32`, samples per channel). Returns 44 bytes, all integers little-endian: `RIFF`, chunk size `36 + data`, `WAVE`, `fmt ` with size 16, format 1 (PCM), channel count, rate, byte rate `rate * channels * 2`, block align
`channels * 2`, 16 bits per sample, `data`, and the data size `frames * channels * 2`. The sizes are 32-bit and are not checked for overflow: `frames * channels * 2` would exceed 4 GiB only for a capture far longer than
the 60 s limit allows. Pure. See also: test `wav_header_is_16_bit_pcm`.

### `capture` [@ANCHOR: bench_mcp_rx888_capture]

The tool `bench_rx888_capture` (tier `read_config`): records a few seconds of one channel to a 16-bit WAV file. Needs `radiod` running. Receive only.

| Argument (JSON key) | Type | Range / default | Meaning |
|---|---|---|---|
| `freq_hz` | number | 10000 to 30000000, required | Carrier frequency, Hz. |
| `seconds` | number | 0.1 to 60, default 5 | Recording length. |
| `kind` | string | `iq` (default) or `audio` | I/Q (two channels, I then Q) or demodulated audio (one channel). |
| `mode` | string | `usb`, `lsb`, `cw`, `am` (default), `fm` | Demodulator for `audio`; for `iq` the mode is fixed to raw I/Q and `mode` is ignored. |
| `gain_db` | number | -20 to 160 | `iq` only: a fixed gain; error if given for `audio` (which uses AGC). Omitted: chosen so the noise sits near -30 dBFS. |

Sequence: joins the data group, opens a channel at SSRC `ssrc_base + 2` with a 5 s lifetime, and for I/Q waits 400 ms, reads the baseband power and sets the gain (the given one, or `-30 - power`, clamped to -20..160;
without a measurable power and without `gain_db` it fails). It checks that `radiod` announces a payload type, 1 or 2 channels, a sample rate (12 kHz, or 24 kHz for FM, as `radiod` reports) and 16-bit big-endian PCM,
then receives RTP packets for up to `seconds + 3` s or until enough samples arrive, renewing the channel's lifetime every second and ignoring packets of other SSRCs or a different payload format (counted in
`rtp_skipped`). The channel is always removed. The samples go to `rx888_<name>_iq_<ms>.wav` or `..._audio_<ms>.wav` in `BENCH_MCP_OUT`.

Returns `wav`, `kind`, `mode`, `frequency_hz`, `sample_rate_hz`, `channels`, `frames`, `seconds` (actually captured), `rtp_packets`, `rtp_lost`, `rtp_out_of_order`, `rtp_restarts`, `rtp_skipped`, `gain_db` (iq only),
`rms_dbfs` (null for silence) and `peak_counts`. Errors: argument ranges; `kind` not `iq` or `audio`; `gain_db` with `audio`; cannot join the data group; commands not acknowledged; the announcements above missing or wrong;
`no audio arrived from radiod for this channel` (with next steps); the file cannot be written. A recording shorter than requested (packets lost, or the deadline reached) is returned as is, not an error: compare `seconds`
with the request and look at `rtp_lost`. Blocks up to `seconds + 3` s plus the settling times under the instrument lock. Does not transmit. See also: test `capture_writes_iq_and_audio_wavs`; the hardware check
`tests/hil_rx888.rs`.
