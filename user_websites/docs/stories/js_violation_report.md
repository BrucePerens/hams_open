# `user_websites/static/src/js/violation_report.js`

The "Report a violation" modal on a user's page is opened by a button that names the address being reported. Tests: `static/tests/violation_report.test.js` (hoot unit tests on real DOM nodes). The class `ViolationReportModal` is registered as the public interaction `user_websites.ViolationReportModal` with the selector `.user-websites-report-container`, so it starts on pages that contain the report widget. The modal itself (`reportViolationModal`) and its form are in `views/user_websites_templates.xml`; the server side of the submission is `report_violation()` in `controllers/main.py`.

### `ViolationReportModal.start()` [@ANCHOR: user_websites:js_violation_report_start]

Lifecycle method called by the public-interaction framework when the page has a `.user-websites-report-container`. It looks up the element with id `reportViolationModal`; if there is one it adds an event listener for Bootstrap 5's `show.bs.modal` event, bound to `_onModalShow`, which fires just before the modal becomes visible. If the page has no such element it does nothing and raises no error. No arguments, no return value, no network access. Called once per page load, so the listener is added once. Test: `start makes the report modal's show event fill in the form, and does nothing when the page has no such modal` in `static/tests/violation_report.test.js`.

### `ViolationReportModal._onModalShow(ev)` [@ANCHOR: user_websites:js_violation_report_on_modal_show]

Handler of the modal's `show.bs.modal` event. `ev` is the Bootstrap event; `ev.relatedTarget` is the button that opened the modal and `ev.currentTarget` the modal. If there is no related target (the modal was opened by code) it returns at once and leaves the form untouched. Otherwise it copies the button's `data-url` attribute into the form field `input[name="url"]` (the page being reported), and clears the `textarea[name="description"]` and `input[name="email"]` left from a previous report; fields missing from the modal are skipped without error. Nothing is sent; the visitor then fills the form and posts it to `/website/report_violation`. Because the address comes from a data attribute the server still treats the posted `url` as untrusted and checks it. Tests: three tests in `static/tests/violation_report.test.js` (address injected and old input cleared; nothing happens without a related target; a modal without the optional fields is tolerated), and the tour `test_tour_violation_report`, which files a report in a real browser.
